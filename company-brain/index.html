A great new hire reads old tickets, asks around, notices when the docs are out of date, and eventually writes down how things really work. Tacit does the same, for every procedure, and keeps doing it.

Why we're building this

a short note, not a pitch

We've both sat in the support queue. The best person on the team was never the one who'd read the most docs. It was the one who remembered that one customer, knew which rule had quietly changed, and knew who to call when payroll was due in the morning.

When companies brought in AI agents, that person's knowledge was the first thing to go missing. The agents were polite and fast, and wrong in ways that cost real customers real money.

Tacit is our attempt to write down what those people know. Their names stay on it, a human confirms every change, and the agent is honest when it doesn't know. We'd love to show you what your team knows.

Open Procedure Schema · v0.3

The format agents run

What your team knows, written so an agent can follow it and a person can still read it. It exports as a skills file and as portable JSON, and we plan to publish the format openly so it isn't locked into one vendor.


        

      

      

        
What's in a procedure

        

          
triggerIntents and phrases that route a ticket here, plus any customer-specific match.

          
inputsFacts the agent must fetch before acting, and which system holds each one.

          
stepsChecks, actions, escalations and replies. if nodes carry a machine-testable condition.

          
guardrailsThings the agent must never do, learned from incidents and policy.

          
provenanceTickets, threads and calls behind every step, with agreement and confidence.

          
driftVersion, the date the current behavior started, and open drift flags.

        

        
If a procedure is below 60% confidence, the agent doesn't guess. It hands the conversation to a person and says why.
